# Khmer test corpus

Test cases shared by every KTE implementation and by upstream ports of the width rule.

## Format

`khmer_corpus.json` is a list of cases:

| Field | Meaning |
|-------|---------|
| `id` | Stable unique identifier, e.g. `word-0003` |
| `category` | `consonant`, `independent-vowel`, `dependent-vowel`, `subscript`, `coeng`, `diacritic`, `punctuation`, `numeral`, `symbol`, `mixed`, `word`, `sentence`, `paragraph` |
| `text` | The exact Unicode text (never normalized) |
| `spec` | Spec areas this case tests, e.g. `["width", "segmentation"]` |
| `expected` | Generated: `clusters`, `half_units` per cluster (`null` for non-Khmer), and total `wide` / `compact` widths |
| `note` | Optional explanation |

## Expected values

Expected values are generated by an independent Python implementation of the spec, not by the Rust code, so the two check each other:

```sh
python3 tools/spec-ref/kte_spec_ref.py          # fill in expected values
python3 tools/spec-ref/kte_spec_ref.py --check  # CI: fail if out of date
cargo test -p kte-unicode --test corpus         # Rust must match
```

## Adding cases

Add text that breaks somewhere, and note where in `note` (terminal, font). Then run the generator above. Native readers: please check that each `text` is spelled correctly.
