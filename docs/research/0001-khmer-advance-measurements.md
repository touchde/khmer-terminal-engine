# Research 0001: Khmer advance measurements

- **Date:** 2026-11-09
- **Phase:** 0 (width spec)
- **Tool:** [`tools/kte-measure`](../../tools/kte-measure/src/main.rs)
- **Question:** How many cells should each Khmer codepoint take? In particular, should spacing vowels count as 0 or 1? (Open question in the [width spec](../../spec/kte-width-spec.md) and [ADR 0002](../adr/0002-width-from-codepoints.md).)

## Method

Every Unicode Khmer font installed on the development machine was shaped with `harfrust`, the HarfBuzz project's Rust port. That was 160 fonts, 9 of them common system/UI fonts. Advances are expressed in **consonant units**: the median advance of a Khmer consonant in the same font.

1. Each base character, spacing sign, non-spacing sign and subscript was measured on its own.
2. Candidate width rules were evaluated against 188 syllables from the test corpus and common sentences. For each syllable, *fit = measured advance ÷ rule width*. A terminal can scale its Khmer font once, globally, so what matters is how much the fit **varies** between syllables. That variation shows up on screen as squeezed syllables or gaps.

## Findings

1. **The "spacing vowels = 0 or 1" question has no good answer.** Single vowels (ា េ ែ ៃ ើ ះ ៈ) add **0.5** consonant; two-part vowels (ោ ៅ ៀ ឿ) add **1.0**.
2. **Base consonants are not all the same width.** ឈ and ណ are 2 consonant units; ឃ ញ ឍ យ ល ស ហ ឡ are 1.5; រ and វ are 0.5.
3. **Most subscripts add nothing**, but 8 add 0.5: ្ឃ ្ឈ ្ឍ ្ប ្យ ្រ ្ឞ ្ស.
4. **Non-spacing signs add 0**, as expected.
5. **Every width is a multiple of 0.5 consonant, and it is stable across fonts.** The 10th–90th percentile ranges are narrow.
6. Rules with **1 cell = 1 consonant** fit at best 72% of syllables (within ±20%). The rest show half-cell gaps or squeezing.
7. With **1 cell = half a consonant** (rule I), the per-codepoint table fits **96% of syllables across all fonts and 100% for the common UI fonts**.

| Rule | Good fit, all fonts | Good fit, common fonts |
|------|---------------------|------------------------|
| A. Bases = 1, spacing signs = 0 (current draft, option 0) | 42% | 41% |
| B. Bases = 1, spacing signs = 1 (current draft, option 1) | 54% | 53% |
| G/H. Measured widths, rounded to whole consonants | 72% | 62% |
| **I. Measured widths in half-consonant cells** | **96%** | **100%** |

## Implication: the trade-off

Rule I means a typical Khmer consonant occupies **2 cells**, like a CJK character. Alignment becomes nearly exact, but the terminal must decide how large to draw Khmer:

- **Fill the cells.** Khmer is drawn at about 1.9× the Latin font size: large, and the stacks need more line height.
- **Draw at a natural size** (about 1.3–1.5× Latin). Every syllable gets the same proportional padding, which reads like slightly wide letter spacing. It is even, not random gaps.

The alternative (1 cell per consonant) keeps Khmer compact, but about a third of syllables get visible half-cell gaps or squeezing.

## Limitations

- The 188-syllable sample is small and has not yet been checked by native readers. A larger, reviewed corpus is needed.
- Fonts come from one machine. Windows (Khmer UI, Leelawadee UI, DaunPenh) and Linux defaults still need measuring.
- Subscript widths depend on the coeng before them, so a plain per-codepoint `wcwidth()` cannot express this rule. Implementations must look at coeng + consonant pairs (see spec §4).

## Reproduce

```sh
cargo run -p kte-measure --release -- ~/Library/Fonts /Library/Fonts /System/Library/Fonts
```
